# P0 Railway-Only Native Routing — Root Cause and Fix

**Date:** 2026-08-25  
**Author:** Manus AI  
**Status:** PASS — source and build environment corrected; new APK required for device verification

## Executive conclusion

The device screenshot proved that RecoFree APK traffic was sent to `https://recobase-vhsxu5ua.manus.space/api/minimal-gpt-proxy`, which returned HTTP 404. The production Railway fallback in the repository existed, but it was overridden at build time by `EXPO_PUBLIC_API_BASE_URL` before the fallback could be reached.

> **Root cause:** `getApiBaseUrl()` trusted the injected public URL before the hardcoded Railway production URL. The managed build environment injected the Manus deployment domain, so the native APK embedded that domain even though `PRODUCTION_API_URL` pointed to Railway.[1]

The build variable is now Railway. Native Android/iOS builds ignore every injected API-base override and always return the hardcoded Railway URL. Hosted web deployments also ignore injected Manus domains; only `localhost` and `127.0.0.1` may use a local development API.[1]

## Before and after

| Layer | Before | After |
|---|---|---|
| Native base URL priority | Injected `EXPO_PUBLIC_API_BASE_URL` won | Hardcoded Railway always wins on Android/iOS |
| Managed build variable | Manus deployment URL | `https://railwayappdashboard-production.up.railway.app` |
| Minimal proxy URL | Manus deployment `/api/minimal-gpt-proxy` | Railway `/api/minimal-gpt-proxy` |
| Extraction provider | Forge could win when both keys existed | Direct OpenAI only on Railway |
| Forge default URL | Active fallback in `server/_core/llm.ts` | Removed from active extraction code |
| Privacy | `store:false` remained active | `store:false` remains active |
| Legacy fallback | Minimal route has no legacy fallback | Unchanged |

## Why the earlier scan missed it

The earlier scan verified tracked production constants and found the hardcoded Railway fallback. It did **not** simulate a native build with a malicious or incorrect injected `EXPO_PUBLIC_API_BASE_URL`, and it did not inspect the ignored managed-project configuration that controls build-time public variables. That was an incomplete validation method.

The new regression suite explicitly simulates a Manus `.space` override on Android, a Manus sandbox override on iOS and a Manus deployment override on hosted web. All must resolve to Railway. It also verifies the active build variable, Railway health, minimal-proxy URL construction, direct OpenAI extraction and absence of a Forge provider branch.[2]

## Remaining Manus-template files

The repository still contains generic template helpers for Data API, image generation, voice transcription and owner notifications. The scan found no RecoFree client consumer for Data API, image generation or voice transcription. `system.notifyOwner` remains registered as an admin-only template route, but no RecoFree client call to it exists.

These files were **not deleted** because the project rule requires proof of complete non-functionality before deletion. They are not in the active native API-base, minimal-proxy, nano or extraction call paths. Their removal should be handled as a separate audited cleanup after backup/server-switch verification.

## Device acceptance

A new APK is required because v1.2.99 has the wrong URL embedded at build time. The corrected APK must show:

```text
Route: minimal-proxy | store:false
URL host: railwayappdashboard-production.up.railway.app
legacyRouteUsed=false
```

It must never show `recobase-vhsxu5ua.manus.space` for any Elias, Kim, extraction, refresh, upload or nano request.
