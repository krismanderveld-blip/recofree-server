SCOPE:
This specification defines one fully implemented therapeutic module (PAAL01) and one profile feature (Draaglast/Draagkracht balkmetafoor) for the Elias persona in RecoFree. PAAL01 helps users in addiction recovery identify and map their personal support pillars (people, routines, places, beliefs). The balkmetafoor feature provides a qualitative visual balance between what weighs the user down (draaglast) and what holds them up (draagkracht). PAAL01 introduces and explains the balkmetafoor at first use.

OUT_OF_SCOPE:
- Kim persona activation
- caregiver support
- diagnosis
- numeric scoring of draaglast/draagkracht
- gamification (no points, badges, streaks, levels)
- server-side memory
- OpenAI memory
- store:true
- replacing existing modules
- changing existing crisis or safety logic
- cosmetic refactoring

CORE_PHILOSOPHY:
Engine beslist, GPT voert uit.

ARCHITECTURE RULES:
- The deterministic engine decides module activation.
- GPT only generates language from a deterministic prompt payload.
- Crisis protocol overrides always.
- No diagnoses.
- No fixed identity labels.
- No pathologizing.
- Data remains local on device.
- store:false for every GPT/provider call.
- No server-side memory.
- No cosmetic refactoring.
- Strict persona separation.
- Elias-only modules may never activate for Kim.
- Kim may never read these modules, their memory patches, logs, state, prompt payloads, or derived projections.
- Elias modules may not read Kim data.
- Module memory must be written locally through existing deterministic memoryWriteRouter.
- The memory integration directive is mandatory and active at every relevant turn, not only session start and not only the first 1-2 messages.

NON_NEGOTIABLE SAFETY:
- Crisis protocol overrides PAAL01.
- If suicide/self-harm, acute danger, severe intoxication, medical emergency, or imminent relapse appears, route to existing crisis/relapse/safety modules before PAAL01.
- PAAL01 may bridge back after stabilization.
- PAAL01 never minimizes consequences of behavior.
- PAAL01 never excuses harmful behavior.
- PAAL01 never diagnoses.
- PAAL01 never pathologizes absence of pillars.
- PAAL01 never says the user is alone/broken/unsupported as a clinical conclusion.
- PAAL01 may name the absence of pillars as a current situation that can change, not a fixed state.

============================================================
MEMORY INTEGRATION PRINCIPLE — BEARGUMENTEERD PER LAAG
============================================================

PAAL01 is primarily an inventariserend/reflectief module, not a pattern-detection module like ROL01/DRIEREGEL01. Memory layer usage is therefore different:

1. buffer — VERPLICHT
   Reason: PAAL01 activation status, current intervention type, and turn directive must be available within the same API call for consistent prompt assembly.

2. state.dat — VERPLICHT
   Reason: The active therapeutic frame (steunpilaren_inventaris) and session-level activation tracking must persist across turns within the same session.

3. user.dat — VERPLICHT
   Reason: moduleUsage tracking is required for all modules. Additionally, the user's identified steunpilaren are durable cross-session data that must be available for greeting context and later-turn relevance.

4. projections.dat — NIET VERPLICHT (optioneel bij sterke overtuiging)
   Reason: PAAL01 is inventariserend, not belief-detecting. It does not primarily uncover inner rules or survival assumptions. However, if during steunpilaren reflection a user expresses a strong belief like "ik heb niemand" or "ik kan op niemand rekenen", a single belief MAY be written as a handle/antidote. This is optional, not automatic.

5. logs.dat — VERPLICHT
   Reason: Encrypted event logging is required for all therapeutic module activations for cross-session continuity and safe summary availability.

MANDATORY LAYERS ON ACTIVATION: buffer, state.dat, user.dat, logs.dat
OPTIONAL LAYER ON ACTIVATION: projections.dat (only when strong belief detected)

Read/use requirement:
- At every later relevant turn, the engine must read buffer/state.dat/user.dat/logs.dat.
- At every later relevant turn across sessions, the engine must read user.dat/logs.dat and, if current state makes it relevant, include a compact memory hint in the GPT prompt.
- This is not keyword-gated.
- This is not limited to greeting.
- This is not limited to the first 1-2 turns.
- The context assembler must evaluate module relevance every turn using moduleUsage, stored steunpilaren, recent logs, and current message semantics.
- If relevant, GPT receives a hard directive to reference stored steunpilaren gently.
- GPT must not expose memory mechanics or say "ik heb opgeslagen".

2. DRAAGLAST/DRAAGKRACHT BALKMETAFOOR — PROFIELFEATURE
============================================================

FEATURE_NAME:
Draaglast/Draagkracht balkmetafoor

LOCATION:
Profile screen (app/(tabs)/profile.tsx) — Elias-only section

RELATIONSHIP TO PAAL01:
- PAAL01 introduces and explains the balkmetafoor at first use (triggerContext = FIRST_USE_INTRODUCTION).
- After introduction, the user can edit the balkmetafoor independently from the profile screen.
- PAAL01 may reference existing balkmetafoor entries in later sessions as context.
- The balkmetafoor is NOT a module — it is a user-editable profile feature.

HOW THIS DIFFERS FROM MOOD SLIDERS:
- Mood sliders are NUMERIC (0-100 scale) and system-managed.
- The balkmetafoor is QUALITATIVE (free text/tags) and user-edited.
- Mood sliders measure current emotional state.
- The balkmetafoor maps structural life factors (ongoing stressors vs. ongoing supports).
- Mood sliders update every session via analysis pipeline.
- The balkmetafoor updates only when the user chooses to edit it.
- There is NO numeric score derived from the balkmetafoor.
- There is NO gamification (no progress bars, no levels, no streaks).

3. PAAL01 MODULE SPEC
============================================================

MODULE_ID:
PAAL01

MODULE_NAME:
Steunpilaren inventaris

PERSONA:
Elias only

THERAPEUTIC BASIS:
- Positive psychology: identifying existing strengths and resources
- Recovery capital framework: mapping what supports recovery
- ACT values-based living: connecting to what matters
- MI affirmation: recognizing existing supports
- Non-diagnostic, non-pathologizing
- Purely inventariserend (mapping) and reflectief (reflecting)

CLINICAL INTENT:
Help the user identify and map their personal support pillars — people, routines, places, beliefs, activities — that hold them up during recovery. No scoring, no diagnosis. Pure inventory and gentle reflection.

ACTIVATION:
Engine detector on contextual triggers:
1. STABLE_REFLECTION: User is in GROEN/GEEL zone, stable moment, no crisis, no high craving. Engine may offer steunpilaren reflection as a positive intervention.
2. POST_DIFFICULTY_REMINDER: After a difficult moment (previous session was ORANJE/ROOD, now stabilized to GROEN/GEEL), remind user of existing pillars.
3. FIRST_USE_INTRODUCTION: First time PAAL01 activates (moduleUsageCount === 0). Introduces concept + balkmetafoor.
4. PERIODIC_UPDATE_INVITATION: sessionsSinceLastPaal01 >= 14 and zone is GROEN/GEEL. Invite user to review/update their pilaren.

CORE MESSAGE:
"Recovery does not happen in isolation. You already have things that hold you up — people, routines, places, beliefs. Naming them makes them visible and usable."

FORBIDDEN:
- never diagnose
- never pathologize absence of pillars
- never say "you have no support"
- never say "you are alone"
- never say "without these you will relapse"
- never create dependency on the module
- never force the user to name pillars
- never judge quality of pillars
- never compare to other users
- never gamify (no scores, badges, streaks)
- never expose memory mechanics
- never say "ik heb opgeslagen"
- never reference Kim data
- never minimize crisis

3.3 PAAL01 INTERVENTION TYPES WITH EXAMPLE OUTPUT
============================================================

Intervention 1:
FIRST_USE_INTRODUCTION

Use when:
- moduleUsageCount === 0, first time PAAL01 activates.

Example:
"Herstel doe je niet alleen met wat je moet veranderen, maar ook met wat je al hebt. Mensen, routines, plekken, overtuigingen — alles wat je overeind houdt, noemen we een steunpilaar. Ik wil je uitnodigen om die eens in kaart te brengen. Niet om te scoren of te beoordelen, maar om zichtbaar te maken wat er al is. In je profiel vind je straks ook een balans-overzicht: wat weegt aan je, en wat draagt je. Geen cijfers, geen oordeel — alleen zicht."

Intervention 2:
STABLE_REFLECTION_INVITE

Use when:
- zone GROEN/GEEL, user is stable, reflective markers detected.

Example:
"Dit lijkt een rustig moment. Soms is dat precies het goede moment om even stil te staan bij wat je overeind houdt. Wie of wat geeft jou kracht in je herstel? Dat hoeft niet groot te zijn — een wandeling, een persoon, een vaste routine telt ook."

Intervention 3:
POST_DIFFICULTY_REMINDER

Use when:
- user stabilized from ORANJE/ROOD, has existing pilaren.

Example:
"Je hebt een moeilijk moment doorgemaakt en je bent er doorheen gekomen. Eerder heb je benoemd dat [steunpilaar] je helpt. Is dat iets waar je vandaag op kan leunen?"

Intervention 4:
PERIODIC_UPDATE_INVITE

Use when:
- 14+ sessions since last PAAL01, zone stable.

Example:
"Het is een tijdje geleden dat we stilstonden bij wat jou draagt. Kloppen je steunpilaren nog? Is er iets bijgekomen, of iets dat minder steunt dan voorheen?"

Intervention 5:
PILLAR_ACKNOWLEDGMENT

Use when:
- user names a new steunpilaar during conversation.

Example:
"Mooi dat je dat benoemt. [Steunpilaar] klinkt als iets dat je echt draagt. Ik onthoud dat als een van je pilaren — niet als score, maar als herinnering aan wat er al is."
